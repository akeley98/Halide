# How to read this file

These are COVERAGE MILESTONES, not a doc outline and not an ordered to-do list.
Each milestone names a cluster of Halide features that `loopdoc.md` should explain
*correctly and holistically* -- i.e. the doc reads as a coherent whole, and a
micro-agent can reconstruct the loop nest for examples exercising those features
without reading the source.

Because every feature interacts with every other, ordering is a rough guide only.
Skip ahead or double back as judgment dictates.

Marking convention:
  [ ]    not started
  [WIP]  in progress (only one at a time, normally)
  [✅]   the doc explains this well enough that micro-tests covering it pass
         (or fail only for reasons captured in DISCOVERED DOC GAPS below)

"Done" is a judgment call, especially for early milestones -- revisit freely.
