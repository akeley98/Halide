## Two things to surface (not rationalizing)

**1. The third sort field — "then by full name" — is unreachable, and the doc's own example proves it.** The key is `(prefix, first-visitation index, full name)`, and first-visitation index is a per-Func counter, i.e. **unique**. So once you're past the prefix tie, first-visitation *always* decides and full-name can never be the deciding field. The doc even leans on this: `tiebreak_visitation_order` says two distinct-but-`b`-prefixed producers "go by which is visited first, **not alphabetically**" — which only works because visitation sits *ahead of* full name. So the doc presents a three-tier tiebreak whose third tier is dead code given its own second tier.

This isn't wrong (it mirrors a defensive sort key), but it's presented as if all three tiers can decide. My question for you: is Halide's first-visitation index truly always unique per Func (in which case "then by full name" should be flagged as a never-reached fallback, not a real tier), or is there a case where two Funcs share a visitation index and full-name genuinely breaks it? In my implementation it's always unique, so I can't produce a case where full-name decides.

**2. The source citation says "predicate, then values, then args, then specializations," but the body only covers values→args (RHS→LHS) →specializations.** The body is what I can implement and it matches; the "predicate" (RDom where-clause reads) is introduced only in the parenthetical and micro doesn't model it. No example exercises it, so it's latent, not observed — flagging only because the citation adds a category the normative text (and the implementation) skips.

Neither is a contradiction of (a); they're an over-specified tier and an aside. If you want, the clean fix for #1 is to note first-visitation is unique and demote "full name" to "(a final, effectively-unreachable fallback for determinism)" — but I'd rather you confirm the uniqueness assumption first, since that's the kind of thing where the doc author may know something about Halide's walk that my implementation flattened.
