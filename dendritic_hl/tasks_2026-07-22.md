# Schedule/Idea Rating

Schedules have ratings aggregated from commentary;
ideas inherit the rating of their canonical schedule.

* Both `positive` and `negative` non-cancelled reviews
  -> `mixed`

* Otherwise, at least one `positive` non-cancelled review
  -> `positive`

* Otherwise, at least one `negative` non-cancelled review
  -> `negative`

* Otherwise, at least one `lost_interest` non-cancelled review
  -> `lost_interest`

* Otherwise, `neutral`

If an idea turns out to be impossible/impractical to implement, the
pattern will be to make an unchanged schedule canonical and give it a
negative review.

Document the above exception to the "canonicalize when idea
implemented to satisfaction" rule.

# Schedule/Idea Cost Scoring

CLAUDE: be particularly critical for this section.

Higher is worse. To calculate the cost of a schedule:

* Find all benchmarks attached to this schedule
  that are reachable from the current session's benchmark set list
  and have the expected `profiler_version` value for this harness.
  Give a warning for each benchmark discarded due to `profiler_version`.
  If this list is empty, the cost is a "negative infinity" sentinel
  (top of list, to prod agent to benchmark).

* For each unique generator parameters set,
  take the median `wall_time_min`.
  The cost is the lowest such median.

The cost of an idea is:

* The cost of its canonical schedule, if it exists.

* The cost of its parent schedule otherwise.

### TODO Statistical Significance

**Statistical significance is missing from the cost model — this is the session's central lesson, and the doc reverts to point estimates.** Cost = "lowest median `wall_time_min`," and obsolete-tagging fires whenever a child has "a lower cost" — with **no significance margin**. We spent the session proving that ~1% differences are noise unless paired-tested, and we built `wall_time_smallest`/`tail_spread` precisely as an error bar on the min. None of that is used: median-min collapses it to a scalar and compares with `<`. Consequence: obsolete-tagging will **thrash on sub-noise differences** (a schedule 0.3% "faster" by luck silently obsoletes a real idea). At minimum the cost comparison needs a "significantly lower" test (e.g. difference must exceed the `tail_spread`/CI), not bare `<`. This is the biggest gap.

# Private Idea List Changes (Private Session State)

CLAUDE: be particularly critical for this section.

Each idea node in the private idea list is now attached to:

* A pool tag (just a string)

* A cost (calculated on-demand)

The purpose of the pool tag is to allow the agent to enforce some
variety in the to-be-described top ideas list.

Ideas enter the list by:

* Being there initially when the session is created (seed ideas)

* Being added implicitly by `new_idea`
  (todo, remove the implicit addition by session creation)

* Added explicitly.

Get rid of the "forget idea" tool; instead, some pool tags indicate
the idea is hidden by default (maybe `.` prefix just like Unix).
The agent can assign new pool tags to an idea at any time,
or bulk replace one pool tag with another.

NB the idea node -> pool tag mapping is session private state,
not part of the idea node.

Add a tool for querying the top ideas list. This takes the current
ideas list and passes them through a series of transformations before
printing:

* **Pool Filter:** Remove ideas with hidden pool tags (default mode),
  or filter out none (show all mode), or keep only those with a
  specific pool tag (explicit pool argument).

* **Obsolete Tagging:** For each idea in the current list, check all
  child ideas of the canonical schedule.  If the linked idea has a
  lower cost; not counting the "not benchmarked" sentinel, add an
  "obsoleted by [that idea]" tag to this idea.

  (TODO consider superseded side links? This sounds clever,
  but has a lot of subtle implications).

* **Sort and Display:** Sort by cost.
  Then for each pool tag, show the N best ideas (lowest cost).
  Include for each idea its ID, cost, and distance from its root.
  For each obsolete tag, print the obsoleted-by schedule's ID,
  and print the obsoleted-by idea's pool tag (if in the current idea list)
  or a warning if it is not in the current idea list.

This is intentionally not quite like beam search in that we are not
bucketing by level, because my expectation is LLM search will be
less "regimented" than beam search and a single tree level isn't
really a meaningful semantic concept.

This is the reason for the obsolete tagging, which is a more organic
way of removing ideas that are too high up in the tree.

# Session Tools

Sub-sessions will now go through 5 phases:

* Created by main session,
  which no longer implicitly creates the workspace C++ file
  and curent ideas list.

* Private workspace initialization by sub-session. Will be blocked if
  state already exists; this is the new more robust guard for the
  "multiple agents, same session" failure mode.
  Add a `-f`,`--force` option to force reset the workspace.

* Sub-session is used by the sub-agent.

* Sub-session is closed by the sub-agent.

* The main agent "joins" the sub-session,
  which copies some state back to the main session.

## Sub-session Opening

Sub-session creation still takes a prompt ("proposal"), but now
accepts a list of 1+ schedule nodes. Each schedule node gets a new
"Created for session" idea node attached, with the proposal text being the
prompt.


## Sub-session Closing

Session closing gets more complicated.
It promotes a fair amount of private (not git tracked)
session state to public (git tracked) session state.

The session is closed with a JSON file, containing:

* List of output schedule IDs; first one is primary.

* Map of output schedule IDs to pool tags; leave empty for default.

* List of seed ideas to explicitly ignore.

Session closing adds the following state to the catalog:

* Output schedules with pool tags.
  The default pool tag is the pool tag of the parent idea;
  error for root node schedules or hidden pool tags.

* Error if any output schedule has no commentary.

* Freeze private benchmark set list as the output benchmark set list.

* For each output schedule node O, walk the tree up towards the root
  until reaching a seed idea S.
  Add a superseded-by link from S to O's parent.
  Skip if no seed idea reached (could happen due to `new_root`)

Recall the `dh_hl` tool implements atomic catalog edits.


## Session Joining

* Add the parent ideas of the joined session's output schedules to the
  current idea list, with same pool tag as recorded.

* Add the benchmark sets of the joined session to the current session.

Print the IDs of all ideas and benchmark sets added so the agent
can manually undo stuff if needed for some reason.


## Root Schedules

Root schedules kind of break the above is subtle ways:

* No parent idea for adding to current idea list.

* No superseded-by links added.

I need the feature for certain cases (e.g. when I introduced the "answer key").
For now I don't think I'll worry about this unless there's an obvious fix.

Root cause: it feels most natural to me personally to have a private
idea list, not private schedule list, to remind the agent to implement
unimplemented ideas with promising enough parent schedules.
